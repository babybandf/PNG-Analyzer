# WP-5U7 — PNG Analyzer UI 布局与像素重建页面修正

> Work Package：`WP-5U7`  
> Milestone：M5 UI Refinement  
> Status：approved for implementation  
> Depends on：WP-5U2、WP-5U5A、WP-5U5B、WP-505A～WP-505C、WP-5U6C  
> 主要允许路径：`ui/qt/`、`tests/gui/`、本工作包文档  
> 条件允许路径：仅在现有只读 reconstruction view-model 无法表达本工作包要求时，才可对其所属 Qt-free 接口和聚焦测试作最小扩展  
> 禁止路径：`third_party/`、无关 parser/decoder/DEFLATE 实现、无关工作包文档

本工作包是对既有 UI 实现的后续窄范围修订。在 Inspector 导航层级、Reconstruct
正文形式、三栏拖动体验上，以本工作包为准；`WP-5U0` 的 Selection、状态所有权、
异步 generation、数值语义、数据来源和性能约束继续有效。本工作包不授权建立第二套
坐标模型，也不授权 GUI 解析 PNG、重算 Filter 或从调试字符串猜测领域事实。

## 1. 背景

当前 PNG Analyzer 主界面存在以下新增 UI 问题：

1. Chunk List 与中央区域之间的分隔线，在未加载图片时可以拖动；加载图片后可能无法拖动，且鼠标命中区域过窄。
2. 中央区域与 Inspector 之间无法稳定地动态调整宽度。
3. Inspector 中所有功能页平铺在同一行，标签过多、名称被截断、层级不清晰。
4. Reconstruct 页面依赖 Stage 下拉框查看单一阶段，无法从头到尾理解当前像素的重建过程。
5. Reconstruct 页面现有表格和底部调试文本信息割裂、重复，并包含不适合直接面向用户的错误文本。
6. 像素重建缺少当前像素周围的空间上下文，无法直观看出 Filter 计算所使用的相邻点。
7. 当前点和参与计算的相邻点缺少明确、不同语义的背景高亮。

本任务应将这些问题作为一次统一的 UI 修正完成，同时保持现有 PNG 分析、坐标联动和数据模型行为不变。

## 2. 用户可见目标

完成后应达到以下效果：

- Chunk List、中央区域、Inspector 构成稳定的三栏可调布局。
- 无论是否加载图片、图片尺寸多大，两条竖向分隔线都容易命中并可拖动。
- Inspector 使用“一级分类 + 二级页面”组织现有页面。
- Reconstruct 页面成为一份可滚动、可复制、从上到下阅读的当前像素重建报告。
- 报告完整展示目标定位、扫描行、过滤数据、邻域、Filter 公式、逐通道计算和最终像素。
- 邻域按通道分别显示三行，当前像素始终居中。
- 当前像素与实际参与 Filter 计算的相邻点使用不同背景色高亮。

## 3. 实施边界

### 3.1 本任务包含

- 主窗口三栏布局与尺寸策略排查、修正。
- 两条竖向分隔线的命中区域、鼠标光标和状态样式。
- Inspector 现有页面的分组和导航层级调整。
- Reconstruct 页面展示方式重构。
- 像素邻域与 Filter 依赖点的文本化、分通道展示。
- 当前点和计算依赖点的动态高亮。
- 与以上修改直接相关的测试和回归验证。

### 3.2 本任务不包含

- 新增 PNG、DEFLATE、Huffman 或 Filter 解码能力。
- 修改已有 PNG 解码算法或文件解析结果。
- 删除现有 Inspector 业务页面。
- 重做整个应用的主题。
- 重构中央区域内部全部功能页。
- 新增与当前像素重建无关的分析信息。
- 将内部调试数据无筛选地暴露给用户。

## 4. 开发前置检查

开发 Agent 开始工作后，必须先完成以下只读检查，再决定具体组件改法：

- 确认 Qt 版本以及 Widgets、Quick 或混合实现方式。
- 定位主窗口、Chunk List、中央区域、Inspector 的实际组件层级。
- 确认左右区域是否为 `QDockWidget`，中央区域是否包含 `QSplitter`、`QScrollArea`、`QGraphicsView` 或其他尺寸敏感控件。
- 定位图片加载流程中所有尺寸、布局恢复和页面重建操作。
- 定位 Inspector 当前页面实例、信号连接、坐标上下文和刷新入口。
- 定位 Reconstruct 页面的数据来源，区分展示层数据与内部调试字符串。

不要在未确认实际结构前，机械地把所有区域改成新的 `QSplitter`。验收目标是三栏稳定可调，而不是指定某一种组件。

## 5. 工作包 A：三栏布局与分隔线修正

### A1. 复现并定位根因

分别在以下状态记录三栏尺寸、最小尺寸、最大尺寸和 Size Policy：

1. 应用启动且未加载图片。
2. 加载小尺寸 PNG。
3. 加载大于中央视口的 PNG。
4. 切换多个不同尺寸 PNG。
5. 关闭图片回到空状态。

重点检查：

- `setFixedWidth()`、`setMinimumWidth()`、`setMaximumWidth()`。
- `minimumSizeHint()` 是否随图片尺寸放大。
- `QSizePolicy` 是否在加载图片后发生变化。
- 图片加载时是否调用 `setSizes()`、`resizeDocks()`、`resize()` 或恢复旧布局。
- 图片控件是否用原始图片宽度撑大中央区域。
- 子控件是否覆盖分隔线命中区域。
- Inspector 表格或长标签是否把右侧最小宽度撑大。

### A2. 布局行为要求

目标结构：

```text
Chunk List  ↔  Central Area  ↔  Inspector
```

- 三栏必须由一个明确且不冲突的水平尺寸管理结构控制。
- 不得给任意一栏设置不可调整的固定宽度。
- 只设置保证基本可用的最低宽度。
- 图片内容应通过缩放、滚动或视口裁剪呈现，不得决定主窗口三栏的最低宽度。
- 加载、刷新、切换或关闭图片时，不得重置用户本次运行中已经调整的栏宽。
- 拖动一条分隔线时，另一条分隔线不得无故跳回默认位置。
- 若现有 Dock 的关闭、浮动和恢复功能存在，修改后必须保留。

建议初始比例：

```text
Chunk List：20%
Central Area：45%
Inspector：35%
```

建议最低宽度，最终值以真实控件可用性为准：

```text
Chunk List：160–200 px
Central Area：300–360 px
Inspector：320–380 px
```

最低宽度总和不得导致普通窗口尺寸下三栏无法调整。

### A3. 分隔线交互要求

- 两条竖向分隔线的有效命中宽度建议为 6–8 个逻辑像素。
- 鼠标进入命中区域后稳定显示水平调整光标。
- Normal、Hover、Pressed/Dragging 状态应有轻微但清晰的视觉差异。
- 视觉线可以较细，但实际命中区域不能只有 1–2 px。
- 图片贴近分隔线显示时，不得抢走分隔线拖动事件。
- 两条分隔线使用一致的命中和视觉规则。
- 在 macOS 高分屏和普通缩放比例下验证。

跨应用启动保存栏宽属于 P2 增强项；本任务 P0 要求至少保证同一次运行期间不被重置。

仅重新组织现有页面，不新增业务功能：

```text
Image
├─ Reconstruction
├─ Pixel
└─ Format Context

Scanline
├─ Scanline

```

如果真实代码中的页面名称略有不同，开发 Agent 应按功能语义映射，并在交付说明中给出最终映射表。

### B2. 交互要求

- Inspector 顶部显示一级分类。
- 一级分类下只显示对应的二级页面。
- 不复制现有页面实例，不重复建立昂贵的数据模型或解析流程。
- 保留当前坐标、选中 Chunk、Pixel、Scanline、DEFLATE token 等上下文。
- 页面切换不得触发无意义的文件重新解析。
- 标签名称应可辨识，不能继续依赖一排相似的省略号。
- Inspector 变窄时可使用滚动、紧凑标签或溢出菜单，但不得用超大最低宽度撑住整个右栏。
- 默认进入 `Image / Reconstruction`。
- 由其他页面执行“跳转到 Inspector”时，应同时选中正确的一级分类和二级页面。
- 自动切换页面不得改变三栏宽度。

## 7. 工作包 C：Reconstruct 页面重构

### C1. 删除现有展示

从 Reconstruct 正文移除：

- `Stage` 标签和阶段下拉选择框。
- 当前 Channel/Value 表格。
- 页面底部独立的 `Reconstruct: ...` 调试摘要。
- 页面底部独立的 `row ...` 信息。
- 直接面向用户显示的 `row query: error` 等内部错误字符串。

这些信息中对用户有价值的部分，应进入对应计算阶段；无关或重复内容不再显示。

### C2. 新页面形式

- 使用一个可垂直滚动的只读内容区域。
- 页面内容按阶段自然向下排列，不提供局部阶段下拉选择。
- 正文以文本为主，公式和数值使用等宽字体。
- 文本允许选择和复制。
- 长公式允许换行，避免依赖横向滚动。
- 每个阶段有独立标题，标题字号比计算正文大一级，并具有清晰段间距。
- 页面跟随顶部 X/Y 坐标、图像点击和锁定状态自动更新。
- 不新增局部 DEC/HEX 控件；沿用顶部已有的显示进制设置。
- 如有助于理解，可在当前进制后补充另一进制，例如 `251 (0xFB)`。
- 更换目标像素时，只更新展示模型，不重新解析整个文件。

### C3. 阶段结构

至少按以下顺序展示：

1. **目标像素**
   - 图像坐标。
   - PNG 颜色类型、位深、有效通道。
   - 当前解析 Pass；非交错图可显示 Pass 0 或“不交错”。
2. **定位扫描行**
   - Pass、Pass 内行号、图像行号。
   - 像素或样本索引。
   - 扫描行内字节位置。
   - 必要时显示 Filter byte 位置和数据来源。
3. **读取过滤后数据**
   - 按源通道列出当前 filtered 值。
   - 明确数值进制。
4. **像素邻域**
   - 按第 8 节规则显示三行邻域、通道和高亮。
5. **确定过滤算法**
   - Filter 类型。
   - Predictor 公式。
   - 边界取值规则。
6. **逐通道重建**
   - 每个源通道分别列出 `x`、`a`、`b`、`c` 中实际使用的值。
   - 展开 predictor 计算。
   - 展开加法和模 256 过程。
7. **生成最终像素**
   - 源样本值。
   - 必要的位深扩展、调色板解析或 Alpha 补全说明。
   - 最终 RGBA。

不要重复显示与当前像素计算无关的整行调试信息。例如 `row byte 0` 仅在它确实影响当前样本边界处理时，才放入相应阶段。

## 8. 工作包 D：三行像素邻域与分通道展示

### D1. 邻域范围

- 固定显示当前行上方一行、当前行、当前行下方一行，共三行：`y-1`、`y`、`y+1`。
- 列数必须为奇数。
- 默认显示五列：`x-2`、`x-1`、`x`、`x+1`、`x+2`。
- 当前像素始终位于矩阵的正中央，即第二行、中央列。
- 宽屏可扩展为七列，但不得改变当前像素居中的规则。
- 位于图像边缘时，超出图像的格子显示 `—` 或明确的 Out of bounds 占位，不得通过移动窗口使当前像素偏离中心。

### D2. 分通道展示

每个有效源通道分别显示相同布局：

- Truecolor：R、G、B。
- Truecolor + Alpha：R、G、B、A。
- Grayscale：Gray。
- Grayscale + Alpha：Gray、Alpha。
- Indexed color：Index；调色板解析后的 RGBA 在最终像素阶段说明。

不得为源文件不存在的通道虚构重建过程。例如无 Alpha 的 RGB 图片，可以在最终输出阶段说明 `A = 255`，但不应伪造一个经过 Filter 重建的 A 通道。

### D3. 文本布局

邻域采用紧凑、等宽、可复制的文本矩阵或具备相同视觉效果的结构化文本组件：

```text
B 通道
                 x=1199       x=1200       x=1201
y=375            c: 149       b: 137          138
y=376            a: 143      当前: 132         143
y=377               141          132           140
```

上例为三列缩略示意；正式页面默认五列。

每个通道必须保持：

- 相同的列宽和坐标轴位置。
- 相同的当前点位置。
- 相同的高亮语义。
- 不因数值位数或进制变化而破坏对齐。

## 9. 工作包 E：当前点与 Filter 依赖点高亮

### E1. 高亮语义

至少定义三种稳定状态：

1. **当前像素**
   - 使用主色背景，例如蓝色系。
   - 有清晰边框。
   - 单元格内标注“当前”或等价标识。
2. **参与当前 Filter 计算的相邻点**
   - 使用与当前像素明显不同的辅助背景，例如橙色或浅黄色系。
   - 在单元格中标注 `a`、`b`、`c`。
3. **普通邻域像素**
   - 使用普通页面背景。
   - 不添加 Filter 依赖高亮。

当前像素和计算依赖点禁止使用相同背景色。

### E2. 动态依赖规则

按 Filter 类型高亮实际参与 predictor 的相邻点：

| Filter | 当前点 | 高亮的相邻依赖 |
|---|---|---|
| None | 始终高亮 | 无 |
| Sub | 始终高亮 | `a` |
| Up | 始终高亮 | `b` |
| Average | 始终高亮 | `a`、`b` |
| Paeth | 始终高亮 | `a`、`b`、`c` |

切换坐标、通道、图片、Pass 或 Filter 后，高亮和标签必须立即更新，不得残留上一个像素的状态。

### E3. 可访问性与主题

- 背景色必须来自主题色或集中定义的 UI token，不要散落硬编码颜色。
- 浅色和深色主题下都要保证文字对比度。
- 不能仅依赖颜色传达含义；必须同时保留“当前、a、b、c”文字和边框差异。
- 邻域附近提供简短图例：当前像素、参与计算的邻居、普通邻域像素。
- Focus、Selection 和高亮样式不能互相覆盖到无法辨识。

## 10. 算法展示正确性

展示层必须使用解析器提供的真实中间值，不得通过最终 RGB 反推 filtered 数据。

标准 8-bit 情况下，重建公式至少应正确展示为：

```text
None:    recon = x
Sub:     recon = (x + a) mod 256
Up:      recon = (x + b) mod 256
Average: recon = (x + floor((a + b) / 2)) mod 256
Paeth:   recon = (x + PaethPredictor(a, b, c)) mod 256
```

其中：

- `x`：当前 filtered byte。
- `a`：同一扫描行中，向左 `bytesPerPixel` 的已重建字节。
- `b`：上一扫描行同一字节位置的已重建字节。
- `c`：上一扫描行向左 `bytesPerPixel` 的已重建字节。

重要约束：PNG Filter 操作对象是扫描行字节，不应在所有颜色类型和位深下简单假设为逻辑像素。

- 对 8-bit RGB/RGBA，`a`、`b`、`c` 通常可映射到相邻像素的同一通道。
- 对低于 8-bit 的 packed samples、Indexed color 或其他不能一一映射的情况，应展示真实源字节依赖。
- 如果某个 Filter 依赖无法准确对应到单个逻辑像素，不得高亮错误像素；应在计算正文中单独显示源字节位置和值。
- Adam7 图必须使用当前 Pass 的扫描行和采样位置，并正确映射回图像坐标。
- 行首、首行等边界按 PNG 规范使用零值时，正文应明确说明该依赖因边界取 `0`。

## 11. 示例数据验算

以下示例来自当前需求截图，可作为 Average Filter 展示测试用例：

```text
目标像素：(1200, 376)
Filtered：R=251, G=250, B=248

R：a=227, b=225
predictor=floor((227+225)/2)=226
recon=(251+226) mod 256=221

G：a=199, b=195
predictor=floor((199+195)/2)=197
recon=(250+197) mod 256=191

B：a=143, b=137, c=149
predictor=floor((143+137)/2)=140
recon=(248+140) mod 256=132

最终输出：RGBA(221, 191, 132, 255)
```

Average 不使用 `c`，所以该示例中 `c=149` 可以标注位置，但不能使用“参与计算”的背景高亮。切换到 Paeth 时才同时高亮 `a`、`b`、`c`。

## 12. 空状态与错误状态

- 未加载图片：显示简洁空状态，例如“加载 PNG 后可查看像素重建过程”。
- 坐标超界：保留用户输入上下文并说明有效范围，不显示内部异常字符串。
- 当前颜色类型或位深暂不支持完整 trace：显示已知阶段，并在缺失阶段说明具体原因。
- 数据模型返回错误时，日志保留技术细节；页面只显示用户可理解的信息。
- 不允许在页面正文中直接显示 `row query: error` 等原始调试文本。

## 13. 更新触发与状态保持

以下操作应刷新 Reconstruct 内容和高亮：

- 在图像上选择像素。
- 修改顶部 X/Y 坐标。
- 切换文件或重新加载文件。
- 切换 DEC/HEX 显示。
- 当前 Pass、颜色类型或解析上下文变化。

以下状态不得被无关刷新重置：

- 三栏宽度。
- Inspector 一级分类和二级页面，除非发生明确的跨页跳转。
- Lock 状态。
- 当前文件和选中坐标。

## 14. 测试要求

### 14.1 布局测试

- 未加载图片时，两条分隔线均可拖动。
- 加载小图、大图、超大图后，两条分隔线仍可拖动。
- 连续切换至少 10 次不同尺寸图片，栏宽不被重置或锁死。
- 缩小和放大应用窗口后，三栏仍可使用。
- 图片视图贴近分隔线时，鼠标仍容易触发水平调整光标。
- Dock 原有关闭、浮动和恢复能力不回退。

### 14.2 Inspector 测试

- 所有旧页面均能从新分类进入。
- 一级、二级页面跳转正确。
- 长标签不会再次形成一排难以区分的省略号。
- 页面切换后坐标、Chunk 和像素上下文保持正确。
- 不产生重复页面实例或重复信号响应。

### 14.3 Reconstruct 页面测试

- 页面中不存在 Stage 下拉框、旧 Channel 表格和底部调试摘要。
- 所有阶段按顺序在同一个滚动页面中显示。
- 标题字号明显大于正文。
- 公式与正文可复制。
- 更换坐标后所有阶段、数值和最终 RGBA 同步更新。
- 切换 DEC/HEX 后对齐不被破坏。

### 14.4 邻域与高亮测试

- 邻域始终三行。
- 默认五列，当前像素位于第二行、中央列。
- 图像四边和四角位置仍保持当前像素居中，越界位置正确占位。
- 每个有效源通道使用相同结构。
- 当前像素始终使用主背景高亮。
- None、Sub、Up、Average、Paeth 分别高亮正确的依赖点。
- 当前点与依赖点背景色可明显区分。
- 浅色、深色主题下文字可读。
- 仅看文字标签和边框，也能辨认当前点及 `a`、`b`、`c`。

### 14.5 算法与格式覆盖

至少覆盖：

- RGB 8-bit，五种 Filter。
- RGBA 8-bit。
- Grayscale。
- 图像第一行和每行第一个像素。
- 图片四个角。

## 19. 实施记录（2026-08-23）

### 根因与映射

- 三栏根因：主窗口使用两侧 `QDockWidget`，但默认 dock 宽度和 splitter 命中规则未集中设置；图片视图本身没有把原图尺寸设为主窗口最小尺寸。修订后保留 dock 的关闭/浮动/恢复能力，统一将 splitter handle 设为 8 logical px，并只保留 Chunk/Inspector 的可用最小宽度；默认 dock 比例为 20%/45%/35% 左/中/右近似值。
- Inspector 映射：`Image → Reconstruction / Pixel / Format Context`；`Scanline → Scanline / Source`；`Compression → DEFLATE Blocks / Huffman / Decode Trace`。页面实例只创建一次，分组切换不重新解析文件。
- Reconstruct 数据来源：`StageSet` 与 `build_reconstruct_view()` 提供 pass、scanline、filtered/unfiltered offset、FilterTraceEvent 和 native samples；Qt 层只负责报告排版、进制格式化和语义色 token，不从调试字符串或最终 RGB 反推 Filter。
